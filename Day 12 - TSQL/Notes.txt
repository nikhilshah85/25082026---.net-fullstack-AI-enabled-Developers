			TSQL (Transact SQL in SQL Server, also know as PLSQL in oracle and MySQL, db2 etc..)

	1. with SQL there are challenges for developers
		a. programming our queries
			with variable
			with conditions (if, if else, switch)	
			loops 
			exception handling
	2. if you 10 users fire, select * from empInfo
		this query goes through more than 10 steps to return the result
		--they are loose statement- for a query they go through lots of steps for result everytime even if it is the same query, by same user

		so, instead why not create pre-checked, compiled block, where we say, this block will be given only to selective users to whom we have verified the access

		thus we create new objects to meet this requirements

-----------------------------------------------------------------------------
		a. Functions, also called as User Defined Functions (UDF)
		this are used for 
			calculations, conditions, loops, to hide the algo, code logic etc...					not suitable for DML operations
			you used some inbuild functions like, sum, min, concat, trim, getdate etc..				lets create our own functions

		create function functioName(...parameters) 
			returns datatype
		as
		begin
			//your code
			return result
		end


		a function can return only 1 value
		b. function can be used with select statement, and it will run for all the rows


========
		like functions we have another similar object Stored Procedure in sql server

		a. used for DML operations
		b. It can call a function inside the code (between begin and end)
		c. it has different types of parameters (call directions)
			a. in parameter (input - default) - same like u used in function
			b. out parameter (output - here procedures returns this value to user)
				and this is where procedure can return multiple values against 1 value by 				function
			c. in - out parameter, you give input, proc formats it, calculates it, validate it 
			and return you the output
				eg. 
				1234566678 - input
				(123)-(456)-6678


				country - India - input
				phone number - 8987955633 - input
				output - (+91)- 8987955633 - output



			
------------------------------Triggers
	a. this is used for automation of data (only 1 object available to developers for automation)
	b. also called as a custom constraints
	c. this are like events, when something happens (DML), with the data in table or view
		u want sql server to do something for you on its own
	d. it can be a guard for organization as well as per the policy

			some of the scenrios

			a. new employee can be a part of organization only during the working hours
				new insert / update / delete should be allowed only during work hrs
				monday to friday 9-5
		

			b. Triggers are time based
				types of trigger
					before ( eg. for no dml during non work hours)
					after (walmart store for stock info)
					instead of (specially for views) (views based on joins)
